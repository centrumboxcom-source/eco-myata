# Підключення бази даних і запуск магазину

Актуальне підключення БД і безпечне введення токенів: [SECURE-SETUP.md](SECURE-SETUP.md). Потрібні міграції до 006 включно.

> Актуальна повна інструкція: [START-HERE.md](START-HERE.md). Для нової БД використовуйте supabase/bootstrap.sql; якщо 001 вже встановлена — ще не встановлені міграції 002–005 по черзі.

## 1. Створіть Supabase-проєкт

Відкрийте https://supabase.com/dashboard, створіть проєкт і оберіть регіон Європи. Збережіть пароль БД у своєму менеджері паролів. Він не потрібен у коді магазину.

У SQL Editor запустіть **увесь файл `supabase/migrations/001_store.sql` один раз у новому проєкті**. Він створить таблиці, індекси, функції, права доступу та публічний bucket `products` для фотографій. Міграція призначена для нової бази, її не слід повторно запускати поверх наявних таблиць.

Після 001 обов’язково виконайте supabase/migrations/002_launch.sql та supabase/migrations/003_catalog_editor.sql, supabase/migrations/004_commerce_settings.sql і supabase/migrations/005_order_notifications.sql по черзі. Потім, якщо потрібні стартові товари, запустіть `supabase/seed.sql`. Це демонстраційний каталог. Змініть асортимент, фактичні ціни, залишки, склад, алергени, харчову цінність та фото перед відкриттям продажів.

## 2. Додайте параметри середовища

Скопіюйте `.env.example` у `.env.local` і заповніть:

```dotenv
NEXT_PUBLIC_SITE_URL=https://ваш-домен.ua
NEXT_PUBLIC_SUPABASE_URL=https://ваш-проєкт.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=публічний_anon_ключ
SUPABASE_SERVICE_ROLE_KEY=секретний_серверний_service_role_ключ
```

URL та ключі є у Supabase → Project Settings → API / API Keys. Для цього коду використовуйте відповідні anon та service_role ключі проєкту. **Service role має залишатися тільки на сервері:** не додавайте префікс `NEXT_PUBLIC_`, не вставляйте його в браузер, не комітьте `.env.local`, не надсилайте ключ у чат.

На хостингу додайте ті самі значення до environment variables/secrets. Параметри `NEXT_PUBLIC_*` вбудовуються під час збірки — після їх зміни потрібна нова збірка та публікація. Для локальної роботи `NEXT_PUBLIC_SITE_URL=http://localhost:3000`.

Перезапустіть сайт. Після підключення Supabase демонстраційний режим автоматично вимикається. Якщо каталог порожній — додайте товари або запустіть seed.

## 3. Налаштуйте вхід

У Supabase → Authentication → URL Configuration:

- Site URL: ваш повний HTTPS-домен.
- Redirect URLs: `https://ваш-домен.ua/auth/callback?next=/account/reset`, а для розробки — `http://localhost:3000/auth/callback?next=/account/reset`.
- Увімкніть Email provider та підтвердження пошти.
- Налаштуйте власний SMTP для робочих листів підтвердження та відновлення паролів.

Зареєструйте свій обліковий запис на `/account` і підтвердьте email. У SQL Editor призначте адміністратором **тільки свою адресу**:

```sql
update public.profiles
set role = 'admin'
where id = (
  select id from auth.users where email = 'ВАШ_EMAIL'
);
```

Після цього відкрийте `/admin`. Не створюйте політику, що дозволяє користувачам редагувати власну роль. Не вимикайте RLS.

## 4. Заповніть крамницю

В адмін-панелі:

1. Перевірте категорії й батьківські категорії.
2. Додайте товари, склад, фасування, ціну, залишок і теги. Фото JPG/PNG/WebP до 5 МБ завантажуються в Supabase Storage.
3. Заповніть контакти, посилання Instagram, назву, SEO опис та поріг безкоштовної доставки.
4. Перевірте сторінки конфіденційності й доставки та доповніть фактичними даними продавця й умовами роботи.
5. Увімкніть потрібні способи оплати та доставки.
6. Додайте статті. Публічні сторінки показують тільки опубліковані записи.
7. Увімкніть SEO-видимість лише після завершення підготовки.

Зміни в робочій адмін-панелі зберігаються у Supabase. Товар «видаляється» приховуванням з каталогу, щоб не втратити історію замовлень.

## 5. Нова пошта

Додайте серверний ключ:

```dotenv
NOVA_POSHTA_API_KEY=ваш_ключ
```

Ключ береться у бізнес-кабінеті Нової пошти. Після перезапуску сайт підтягує міста й відділення; поштомати фільтруються окремо. Без ключа покупець вводить адресу вручну. Укрпошта й кур’єр використовують ручне введення адреси. ТТН вноситься в деталі замовлення й експортується разом із замовленнями у CSV. Автоматичне створення ТТН у перевізника не реалізовано.

## 6. Оплата

### При отриманні

Достатньо увімкнути цей спосіб у панелі. Комісію за накладений платіж та умови доставки визначає перевізник.

### Monopay

Потрібен активний мерчант еквайрингу:

```dotenv
MONOBANK_TOKEN=ваш_токен
```

Увімкніть Monopay у панелі. Сайт створює рахунок на сервері в копійках. Callback: `https://ваш-домен.ua/api/webhooks/mono`. Підпис `X-Sign` перевіряється за публічним ключем банку; сума та валюта звіряються із замовленням. Apple Pay і Google Pay доступні на сторінці Monobank за підтримки мерчанта та пристрою.

### LiqPay

```dotenv
LIQPAY_PUBLIC_KEY=ваш_публічний_ключ
LIQPAY_PRIVATE_KEY=ваш_секретний_ключ
```

Увімкніть LiqPay у панелі. Інтеграція використовує API v7 та SHA3-256 за поточною документацією Checkout. Callback: `https://ваш-домен.ua/api/webhooks/liqpay`. Повернення покупця на сайт саме по собі не означає успішної оплати.

Спочатку перевірте інтеграцію у тестовому середовищі вашого мерчанта. Живі платежі не виконувалися під час розробки, оскільки ключів не було. Для приватного перегляду Sites банки не зможуть викликати закриті callback-и; реальні платежі запускайте на публічно доступному HTTPS-домені.

### IBAN

Заповніть отримувача та фактичний IBAN у налаштуваннях, потім увімкніть спосіб. Реквізити покажуться після створення замовлення. Автоматична звірка банківських переказів не підключена; факт надходження потрібно перевіряти в банку.

## 7. Instagram і підписка

Для живих фотографій підключеного професійного Instagram-акаунта додайте серверний `INSTAGRAM_ACCESS_TOKEN` з доступом до його медіа. Потрібно налаштувати Meta/Instagram App і підтримувати актуальність токена. Без нього сайт показує власну редакційну галерею. Email-підписки зберігаються в таблиці `subscribers`; автоматична email-розсилка потребує окремого сервісу.

## 8. Перевірка перед стартом

- Зареєструйте звичайного покупця й переконайтеся, що він бачить лише власні замовлення та не має доступу до адмін-панелі.
- Створіть замовлення з оплатою при отриманні. Перевірте суму, залишки й появу в панелі.
- Повторне надсилання того самого запиту не повинно створювати друге замовлення.
- Перевірте промокод із лімітом, мінімальною сумою та датою завершення.
- Перевірте реальний вибір відділення Нової пошти.
- Пройдіть тестовий сценарій банку, зокрема відмову та підписаний callback.
- Замовлення резервує залишок одразу. Неоплачені замовлення контролюйте в панелі. Скасування повертає залишок один раз; оплачений платіж спочатку потрібно повернути та звірити в банку. Автоматичні повернення та звільнення прострочених резервів не реалізовані.
- Перевірте метадані, домен у sitemap, контакти та умови магазину.

## Основні таблиці

| Таблиця | Призначення |
|---|---|
| profiles | Ролі адміністратора й покупця |
| products / categories | Каталог та дерево категорій |
| orders | Контакти, доставка, суми, статуси та знімок товарів |
| promocodes | Правила купонів і лічильники |
| posts | Статті й чернетки |
| reviews | Відгуки з модерацією |
| settings | Налаштування крамниці |
| subscribers | Добровільні email-підписки |

Рекомендовано увімкнути резервне копіювання у Supabase. Міграція та seed зберігаються в проєкті, секрети — окремо.


## Оновлення налаштувань і сповіщень

Якщо вже встановлено міграції 001–003, виконайте по черзі **supabase/migrations/004_commerce_settings.sql**, потім **supabase/migrations/005_order_notifications.sql**. Для порожньої БД bootstrap.sql уже містить усі п’ять міграцій. Наявні міграції повторно не запускайте.

Адмінка → Налаштування: сортування, сторінки каталогу, відсутні товари, формат гривні, статуси наявності, дія кнопки покупки, лейбли, мінімальне замовлення після знижки, власні поля оформлення, соцмережі й години роботи. Натисніть «Зберегти», потім оновіть відкриту вітрину. Дані зберігаються у settings.value.commerce. Нові поля записуються в замовлення разом із назвою поля на момент покупки. Зміна назви пізніше не змінює історію.

Адмінка → Сповіщення та листи: власний Telegram-бот, email адміністратора та лист покупцю через Resend. Секрети TELEGRAM_BOT_TOKEN і RESEND_API_KEY налаштовуються на сервері. Telegram: додайте бота до чату або почніть діалог із ним, вкажіть числовий chat ID. Email: підтвердьте домен у Resend і вкажіть email відправника з цього домену. Жодні ключі зі скриншотів не використовуються.

Черга сповіщень створюється транзакційно разом із замовленням, відправка виконується після збереження. Помилки не скасовують замовлення. Для незалежного оброблення налаштуйте у вашому планувальнику POST /api/notifications/process раз на хвилину з Authorization: Bearer <NOTIFICATION_CRON_SECRET>. Секрет має бути випадковим і приватним. Альтернатива — кнопка «Обробити чергу» в адмінці. Налаштування отримувачів застосовуються до нових замовлень; наявна черга містить знімок адреси та тексту.

Статус «Прийнято сервісом» не гарантує потрапляння в папку «Вхідні». Помилки повторюються вручну. Якщо сервіс не підтвердив результат або процес перервано, статус «Потребує перевірки»: спочатку перевірте отримувача, адже повтор може створити дублікат. Resend використовує ключ ідемпотентності; у Telegram такої гарантії немає.

Документація провайдерів: https://resend.com/docs/api-reference/emails/send-email та https://core.telegram.org/bots/api#sendmessage. Реальну доставку листів і Telegram необхідно перевірити після підключення ваших ключів. KeyCRM і SalesDrive у цьому оновленні не реалізовані.
